# Astro rules

## Rendering
- Site is `output: 'static'`. Every route is pre-rendered; dynamic routes use `getStaticPaths()` fed by content collections.
- Default to **zero-JS `.astro` components**. Add an island only when the component holds client state or reacts to input.
- Pick the laziest hydration directive that works: `client:visible` > `client:idle` > `client:load`. Even the Player hydrates on idle
  (it renders nothing until there is a queue; PlayButtons call the shared controller directly — D-026).
- Never `client:only` unless the component truly cannot render on the server (e.g. WebGL canvas) — and then render a static fallback.
- Pass the minimum serialisable props to islands (ids, small objects). Never pass whole collections or markdown bodies.

## Layouts and navigation
- All pages use `BaseLayout.astro` (which includes `<ClientRouter />`, the persisted Player, the line indicator, theme pre-paint script, skip links,
  and the route-change live region). Station pages use `StationLayout.astro` on top of it.
- The Player is rendered once in `BaseLayout` with `transition:persist="player"`. Do not render players elsewhere; to play something,
  render a `PlayButton` (only for playable tracks — otherwise an external link) fed by `src/lib/content/catalog.ts`.
- Use `transition:name` for shared elements (cover → release hero, photo thumbnail → lightbox). Names must be unique per page: `cover-${release.id}`.
- Transition direction between stations comes from `src/lib/stations.ts` (index comparison), set via `data-direction` on `<html>` in an
  `astro:before-preparation` listener — not hard-coded per page.
- Client scripts must initialise on `document.addEventListener('astro:page-load', …)` and clean up on `astro:before-swap`.
  Never rely on `DOMContentLoaded` alone. Inline `<script is:inline>` only for the pre-paint theme script.
- Use `<a href>` for navigation (prefetch is enabled with `prefetch: { defaultStrategy: 'hover' }`). No JS-only navigation.

## Content access
- Read content only through helpers in `src/lib/content/` (which wrap `getCollection`/`getEntry` and apply sorting, rights filtering and relations).
  Pages must not filter by `rights` or compute relations themselves.
- Render markdown with `render(entry)` → `<Content />`. Lyrics use the dedicated `LyricsSheet.astro` (preserves line breaks, sets `lang`).

## Images and media
- Images: `astro:assets` `<Picture>` / `<Image>` with explicit `widths`, `sizes`, `formats={['avif','webp']}` and required `alt`.
  Hero/LCP image gets `loading="eager"` + `fetchpriority="high"`; everything else lazy.
- Never put raw `<img src="/…">` for content images. Never use remote images without adding the domain to `image.domains` (prefer local).
- Embeds (YouTube, SoundCloud, Bandcamp) only via facade components in `src/components/media/`.

## Head / SEO
- Each page passes `title`, `description`, `ogImage?`, `jsonLd?` to `BaseLayout`. Titles: `«Название» — Станция Видеопарк`.
- Canonical URL and (when enabled) `hreflang` alternates are generated by the layout from `Astro.url` + i18n config.

## Components
- Props typed with `interface Props`; destructure from `Astro.props` with defaults.
- One component per file; PascalCase file names; colocate styles in the component's `<style>` (scoped).
- Use `class:list` for conditional classes; avoid `set:html` except for trusted, build-time-sanitised content.
- Slots for composition; avoid prop-drilling deep trees.
